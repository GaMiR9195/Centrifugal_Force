# Centrifugal Force

Прилипание игрока к плоскостям sub-level'ов Sable. NeoForge 1.21.1.

## Что где лежит

| Файл | Ответственность |
| --- | --- |
| `internal/AdhesionState` | состояние одного игрока: текущая локальная плоскость, переход, ориентация |
| `internal/AdhesionEngine` | тик: поиск sub-level, привязка, смена плоскости, локальная гравитация, отрыв |
| `internal/PlaneTransition` | геометрия перехода: точная дуга внутреннего угла |
| `internal/SurfaceProbe` | лучи по блокам sub-level в его локальном пространстве |
| `internal/AdhesionMath` | swing-поворот, привязка к оси, сглаживание |
| `internal/AdhesionSettings` | все числа в одном месте |
| `mixin/EntitySubLevelUtilMixin` | отдаёт ориентацию самому Sable |
| `client/DebugOverlay` | оверлей в правом верхнем углу |

Все шаги движка — отдельные публичные статические методы (`findCandidate`, `tryAttach`,
`tryPlaneChange`, `cornerIsClear`, `applyCornerPosition`, `applyLocalGravity`, `updateSupport`),
их можно вызывать из своего кода независимо от подписки на тик.

## Точка поворота

Sable вращает хитбокс вокруг ванильной позиции глаз (`transformEntityBoundsCenter`), а не вокруг
ног и не вокруг центра. Поэтому весь мод считает и ставит именно эту точку:
`setPos(pivot - (0, eyeHeight, 0))`.

## Дуга внутреннего угла

При повороте бокса 0.6 x 1.8 x 0.6 вокруг pivot на угол `t` от плоскости с нормалью `n`
самая нижняя точка вдоль `n` оказывается на `dot(pivot, n) - eyeHeight*cos(t) - halfWidth*sin(t)`.
Условие «не входить в плоскость» — это ровно

```
dot(pivot, n) >= plane + eyeHeight*cos(t) + halfWidth*sin(t)
```

Решение как равенство сразу для двух перпендикулярных плоскостей даёт по одной позиции pivot на
каждый угол. Бокс катится по внутренности угла, постоянно касаясь обеих граней и никогда не
входя ни в одну. Те же формулы наоборот дают путь со стены на пол, поэтому оба направления
ощущаются одинаково. Позиция абсолютная и пересчитывается каждый тик, а не накапливается.

## Почему раньше игрока уносило сквозь блоки

Sable определяет унаследованное от sub-level движение как смещение якоря ног за один вызов
`collide()` и применяет его через коллизию только по главному миру. Ориентация читалась на каждом
сабстепе, поэтому поворот плоскости внутри тика превращался в огромную унаследованную скорость,
никак не проверяемую по блокам sub-level, — игрока протаскивало сквозь стену туда, куда
повернулись ноги, и это же значение возвращалось как скорость на следующий тик.

Локальная часть ориентации теперь заморожена на весь физический тик, поэтому этот член ровно ноль.
Часть от самого sub-level по-прежнему берётся из живых поз, так что вращение постройки
наследуется без отставания.

## Камера

Ориентация — только swing от мирового верха к нормали поверхности, без закрутки вокруг неё.
На ровной площадке любого рыска и вращения это единица, и камера остаётся точно там, где была.
Наклон появляется только тогда, когда реально наклоняется хитбокс.

## Прилипание и 360

Привязка щупает все шесть локальных граней из pivot в пространстве sub-level, поэтому крутизна
склона в мировых координатах не важна: у площадки, с которой ваниль заставляет скатываться, под
pivot всё равно есть локальная грань. Ограничения на накопленный угол нет — пол, стена, потолок,
стена и снова пол работают в любую сторону; касание перпендикулярной грани головой — то же самое
событие, что касание боком.

Перед началом перехода вся дуга и место прибытия проверяются лучами; если не пролезает, переход
не начинается.
